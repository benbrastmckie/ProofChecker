## Overview

`docs/development/NAMING_CONVENTION_DEVIATION.md` declares `defsWithUnderscore` closed at 0 "by
genuine conformance", and `lake exe runLinter FormalSystem` agrees — while a textual scan of the
tree finds 71 public and (measured here) 103 private snake_case `def`s outside `Boneyard/`. Every
one is invisible to that linter by one of four independent mechanisms: out-of-closure modules,
the upstream `_1`/`_2` autogenerated-instance heuristic, an in-source
`attribute [nolint defsWithUnderscore]`, and the structural fact that `runLinter` observes a
package by *importing* it, so no `private` declaration is ever in the environment it walks. This
task renames all of them to lowerCamelCase per the rule table in
`NAMING_CONVENTION_DEVIATION.md` ("The naming rule now in force": data — including every
`DerivationTree`-valued result — takes lowerCamelCase; only `theorem`/`lemma` take snake_case),
deletes the one in-source nolint attribute, updates every citation, and corrects the document's
now-false "closed at 0" claim. Done means: a fresh textual scan agrees with the linter rather
than contradicting it, `lake build` is green, `scripts/check-module-invariants.sh` reports ALL
CHECKS PASSED, and the sorry / vacuous / axiom counts are unchanged.

The sibling gate task (558) that makes a fourth reopening *fail a check* is deliberately not part
of this task; 558 depends on 555 and 557 and runs after. This task is the burndown only.

## Goals & Non-Goals

**Goals**:

  table in `docs/development/NAMING_CONVENTION_DEVIATION.md`.
- Every private snake_case `def` outside `Boneyard/` is likewise renamed — the rule table keys on
  what a declaration *produces*, not on its visibility.

  the now-obsolete parts of its `### Naming exemption` docstring section.

  on the strength of a linter that structurally cannot see 174 declarations, and its burndown
  table reflects the re-measured state.

These Goals name **zero new Lean declarations** — see `## Lean Challenge Statements` below.

**Non-Goals**:

  prohibited by the task description and by `context/contracts/plan-compliance.md` Statement
  Fidelity: `Nonempty`-of-data under the same name is a strictly weaker statement. This was tried
  and reverted during 545's implementation (recorded in that task's summary). Keep the signature;
  change only the identifier.

  `FormalSystem/Automation/Tactics/UserTactics.lean` (`tacticApply_axiom`, `tacticModal_t`,
  `tacticAssumption_search`). Legitimate, documented, and Lean-generated from snake_case tactic
  tokens. Leave them alone.

  `limitDomSubtype_countable`, `mcsToPFilter_isPrime`, `tailFilter_neBot`).
  `defsWithUnderscore`'s findings do not include them, the description's 71 does not include
  them, and Mathlib's own instance names carry underscores by convention.
- **`FormalSystem/Automation/DatasetExport.lean`'s 20 structure-projection findings**
  (`DatasetRecord.formula_str`, `frame_class`, `pattern_key`, …). These are auto-generated
  projections of structure *fields* whose names are the emitted JSON field names, so renaming
  them is a data-format change. 555's report §F11 records them as "in **neither** task 557's nor

  exposure as a `user_decision`. Out of scope here; do not re-raise.
- **`Tests/BimodalTest/`'s own 33 snake_case declarations.** Outside the `runLinter FormalSystem`

  files are edited in this task only where they *cite* a renamed `FormalSystem` declaration.
- **Widening the lint closure, adding an invariant, or changing any gate.** That is task 558's
  charter and it depends on this task.
- **Renaming module or file names.** No import line changes anywhere.

## Rollback/Contingency

Every phase is a self-contained, independently green commit (Phases 2, 3 and 4 as single
`atomic-batch` commits; Phases 5-8 one commit per file), so `git revert` of a single phase's
commit restores a green tree without disturbing the others. The renames carry no semantic content
whatever — signatures, proof terms, axiom sets and emitted dataset labels are all invariant — so a
partial rollback leaves the library mathematically identical to its pre-task state.

If a rename cannot be applied because the target name collides with a live declaration and no
longer descriptive name is satisfactory, record the declaration as a
`#### Reasoned Exclusions` entry on the owning phase with the collision as its Evidence, and mark
that phase `[COMPLETED WITH EXCLUSIONS]` — never leave the snake_case name in place silently and
never mark the phase plain `[COMPLETED]`.

If the full `lake build` in Phase 10 fails in a module no phase touched, the cause is a
transitive-elaboration effect rather than a rename; bisect by reverting phase commits newest-first
rather than editing forward.
