generic `TruthClauses.someFuture_iff`/`somePast_iff` are `rw` plus explicit terms, discharging the
`⊤` guard through `top_true`, so they never reach for it. L's own `Truth.some_future_iff` and
`some_past_iff` were ALREADY `[propext]` -- their hand-written proofs took the same route -- so the
generic lemma matches the tighter of the two pre-existing proofs rather than the looser one.

The hazard this gate exists to catch is the opposite direction: a generic proof reaching for
`by_contra`/`push Not`/a classical `simp` lemma where the per-language original did not, which

names whose baselines carry the full classical set still carry exactly it, and `neg_iff` /
`top_true` are still `[propext]` in all four languages, which is what the generic proofs' `rw`-only
discipline was written to preserve.
